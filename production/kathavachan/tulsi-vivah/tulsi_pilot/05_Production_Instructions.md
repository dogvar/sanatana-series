# Codex production brief
Repository context: dogvar/sanatana-series. Guide: https://dogvar.github.io/sanatana-series/tulsi-vivah.html

1. Inspect available local tools and ImageGen skill. Use no paid API without approval. Work outside production website; no deployment or merge.
2. Treat scripts 01 and 02 as locked editorial drafts for production. Read only marked spoken passages; do not voice headings or markup. Flag factual or pronunciation concerns rather than silently rewriting.
3. Verify the key source claims against Devi Bhagavata Purana Book 9 chapters 23–24 and existing guide citations before final production. Report discrepancies for approval.
4. Create host character sheet and scene artwork using storyboard and design brief. Inspect actual images; regenerate significant inaccuracies. Keep source assets.
5. Test natural Hindi and Indian-English voices, ideally warm podcast-style storytellers. Chatterbox or another suitable local engine only if available, licensed and good quality. Generate 30–45 second samples in each language. Verify Tulsi, Tulasi, Shankhachuda, Shaligram, Gandaki and Vishnu pronunciation. Stop for approval before full production. If no suitable voice/tool exists, report blocker instead of substituting poor output.
6. Produce motion-story animation with Remotion, FFmpeg or suitable local tooling: gentle pans, parallax, blinking and environmental movement. No paid video APIs. No continuous talking avatar required. Avoid static slides with identical zooms.
7. After approval, render complete short script in each language. Determine runtime from natural delivery; do not force equal durations or speed up speech. Use identical visual assets with language-specific timing.
8. Music optional, extremely subtle, licensed for intended publication; voice clarity first. Prefer clean narration if no licensed music is available. No sound effects that distract. Target roughly -16 LUFS integrated, true peak <= -1 dBTP; verify actual levels.
9. Add optional SRT subtitles in matching language, correct Indic shaping if burned in, large readable typography. Opening and closing cards include series title, episode title and guide link; no black opening. No autoplay if later integrated into website.
10. Deliver 1920×1080 24fps H.264/AAC MP4 per language, separate MP3 narration per language, SRT files, source project, scripts, artwork/contact sheet and QA report. Audio-only versions should be suitable for accessible website playback later.
11. Inspect rendered frames and listen to both episodes where tooling permits. Report actual checks, measured durations, costs, licensing and limitations. Never claim unperformed review. Preserve all originals.
